# Отчёты и аналитика Concert CRM

API для менеджера реализует финансовый отчёт UC09, поиск UC10 и аналитику UC11 по FR100, FR110 и разделу 1.11 НИРС.

| Метод и маршрут | Назначение |
| --- | --- |
| GET `/concert/{id}/finance/report` | Итоги концерта за период, расчёты по договорам и детализация |
| GET `/analytics/ranking` | Три лучших и три худших проведённых концерта |
| GET `/concert/{id}/finance/forecast` | Прогноз средних расходов планируемого концерта |
| GET `/concert` | Поиск по `starts_from`, `starts_before` и `city` |
| GET `/contract` | Поиск по `number` и `counterparty` |

Отчёт, рейтинг и прогноз принимают `date_from`, `date_to` и `as_of` в формате YYYY-MM-DD. Границы периода включаются. День начала концерта для отбора определяется в UTC. Поиск концертов сохраняет существующий интерфейс с временными метками и исключительной верхней границей `starts_before`.

## Отчёт

Поступления и расходы за период суммируют записи `POSTED` по их направлениям. Сумма возврата учитывается по направлению самой записи. Денежный результат равен поступлениям за вычетом расходов. Фактический расход по бюджету равен исходящим расходам за вычетом их возвратов. Остаток бюджета может быть отрицательным.

Детализация использует `limit` и `offset`, сортируется по дате операции и ID. В ней доступны ссылки, основания и идентификаторы журнала. Пагинация не влияет на итоговые суммы.

Расчёт по договорам накопительный. Он охватывает связанные операции на дату `as_of` включительно и договоры, подписанные к этой дате. Для договора чистая оплата равна сумме операций его направления за вычетом операций обратного направления. Остаток и переплата показываются отдельно. Дата среза применяется к `occurred_on` и использует текущий статус журнала. Исторические статусы на момент среза не восстанавливаются.

## Рейтинг

Отбираются проведённые концерты, начавшиеся в заданный период. Их результат рассчитывается по операциям этого периода до `as_of` включительно. Концерт без таких операций получает нулевой результат. При равном результате порядок задают дата начала и ID по возрастанию. Каждый список содержит до трёх строк, а `count` показывает размер всей выборки.

## Прогноз

Берутся проведённые концерты с положительным бюджетом, начавшиеся в период истории и завершившиеся к дате среза. Фактические расходы считаются накопительно до среза. Отсутствие учтённых записей, наличие черновиков расходов или отрицательный рассчитанный расход считаются признаками неполной истории. Ответ содержит число пригодных наблюдений и число неполных. При неполной истории, числе пригодных наблюдений меньше 10 либо нулевом бюджете планируемого концерта возвращается причина и `forecast: null`.

Для каждого наблюдения вычисляется отношение фактического расхода к бюджету. Среднее отношений и границы 95%-го интервала Стьюдента для среднего умножаются на бюджет планируемого концерта. Выборочная дисперсия использует делитель `n - 1`. Границы и оценка расходов округляются до копеек. Интервал описывает неопределённость среднего и не задаёт диапазон расходов отдельного концерта.

Независимый пример использует отношения от 0,1 до 1,0 с шагом 0,1 и бюджет 1000 ₽. Среднее равно 0,55, выборочная дисперсия равна 11/120. Численное интегрирование плотности Стьюдента даёт квантиль 2,262157162798 при 9 степенях свободы. Оценка составляет 550,00 ₽, границы среднего — 333,41 и 766,59 ₽.
