# Договоры — FR070 и UC06

Все маршруты доступны менеджеру через [серверную сессию](access-api.md).

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/contract` | Список и поиск |
| GET | `/contract/{id}` | Карточка |
| POST | `/contract` | Создание черновика, HTTP 201 |
| PATCH | `/contract/{id}` | Редактирование черновика |
| POST | `/contract/{id}/activate` | Активация черновика |

При создании передаются `number`, `signed_on` в формате YYYY-MM-DD, `concert_id`, `counterparty_id`, `kind`, `subject`, `amount` и `direction`. Сумму можно передать строкой с точностью до копеек. Договор `MAIN_SHOW` учитывает гонорар (`IN`) и требует совпадения контрагента с организатором. Договор `SERVICE` учитывает стоимость работы подрядчика (`OUT`).

Договор создаётся в статусе `DRAFT` с версией 1. Концерт указывается при создании. Для изменения черновика передайте текущую `version` и изменяемые поля. Для активации достаточно тела `{"version": 1}` с актуальной версией. Каждое изменение увеличивает версию и сохраняет аудит вместе с договором. HTTP 409 означает конфликт версии, состояния, контрагента или уникальности.

Фильтры списка `number` и `counterparty` ищут подстроку без учёта регистра по номеру договора и названию контрагента. При передаче обоих фильтров должны выполняться оба условия. `concert_id` ограничивает поиск договорами одного концерта. Пагинация использует `limit` (1–100, по умолчанию 20) и `offset` (по умолчанию 0).

При активации проверяются фактические связи и отсутствие другого действующего основного договора. Активация и подтверждение концерта используют общую транзакционную блокировку. Частичный уникальный индекс PostgreSQL обеспечивает правило одного `ACTIVE MAIN_SHOW` на концерт. После активации концерт подтверждается отдельным запросом к `/concert/{id}/confirm` с текущей версией концерта. Защита связанных финансовых записей обеспечивается внешним ключом `ON DELETE RESTRICT`.
