# Привлечение подрядчиков — FR060 и UC05

Маршруты доступны менеджеру через HTTP Basic.

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/engagement` | Добавить работу, HTTP 201 |
| GET | `/concert/{concert_id}/engagement` | Получить работы концерта |
| POST | `/engagement/{id}/agree` | Согласовать работу и привязать договор |
| POST | `/engagement/{id}/complete` | Отметить выполнение |
| POST | `/engagement/{id}/cancel` | Отменить работу |

При создании передаются `concert_id`, `counterparty_id`, `description`, `due_at` с часовым поясом и положительная `agreed_amount` с точностью до копеек. Новая работа получает статус `PLANNED` («Планируется») и версию 1.

Согласование принимает `version` и `contract_id`. Сервис сверяет концерт, контрагента и сумму исходящего договора `SERVICE`, затем сохраняет ссылку и статус `AGREED` («Согласовано»). Активация договора является отдельным действием. Каждый договор связан максимум с одной работой. Если связанный договор ещё черновик, его можно исправить с сохранением вида, контрагента и суммы работы.

Выполнение принимает `version` и переводит согласованную работу в `COMPLETED` («Выполнено»). Финансовый журнал при этом остаётся без изменений. Отмена принимает `version` и необязательную `reason`, переводит планируемую или согласованную работу в `CANCELLED` («Отменено») и сохраняет договорную связь. Выполнение и отмена являются конечными состояниями.

Переходы блокируют строку работы, сверяют версию и записывают аудит в той же транзакции. Конфликт состояния, версии или связи возвращает HTTP 409. Отсутствующая карточка даёт HTTP 404, некорректные входные поля или ссылки в теле запроса — HTTP 422.

Список включает все состояния, упорядочен по ID и поддерживает `limit` (1–100, по умолчанию 20) и `offset` (по умолчанию 0). Ответ содержит `items`, `total`, `limit` и `offset`.
